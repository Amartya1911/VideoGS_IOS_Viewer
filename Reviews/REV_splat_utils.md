# Code Review: splat_utils.mm

## Overview
`splat_utils.mm` is a small but critical **Objective-C++** utility file.
Its sole purpose is to provide a **CPU-side sorting function** that is accessible to Swift.

**Why C++?**
Because the C++ Standard Library (`std::sort`) is incredibly fast and optimized. While Swift has `sort()`, passing massive pointers of raw memory back and forth between Swift and C structs can be clunky. C++ handles raw memory pointers (`void *`) very natively.

-   `#include <algorithm>`: Imports the C++ algorithms library, which contains `std::sort`.
-   `#import "../ShaderTypes.h"`: Imports the shared struct definitions so the code knows what a `Splat` is.

## 2. The `sort_splats` Function
**Location**: Lines 23-48

This is the only function in the file. It is marked `extern "C"`, which prevents "name mangling". This means Swift or other C files can find and call this function just by its name `sort_splats`.

### Function Arguments:
-   `void * splat_buffer`: A pointer to the main GPU buffer where splat data (positions, colors) is stored.
-   `void * temp_splat_buffer`: A pointer to a temporary "scratchpad" buffer of equal size.
-   `void * splat_index_buffer`: A pointer to the list of "packed depth + index" values generated by the GPU.
-   `Uniforms uniforms`: (Unused in the active code) Camera state passed for context.
-   `int num_splats`: The total number of points to sort.

### The Logic Steps:

1.  **Casting Pointers (Lines 30-32)**:
    -   The function receives generic `void *` pointers. It casts them to specific types (`Splat *`, `int64_t *`) so it can read/write the data correctly.

2.  **Sorting (Line 36)**:
    -   `std::sort(splat_index, splat_index + num_splats);`
    -   This sorts the `splat_index` array in **ascending order**.
    -   **Magic Trick**: The GPU packed the data as `[Depth (32 bits) | Index (32 bits)]`.
    -   Because the "Depth" is in the high bits, sorting this 64-bit integer automatically sorts by depth! The "Index" part just tags along for the ride.

3.  **Reordering Data (Lines 39-42)**:
    -   Now that `splat_index` is sorted from specific depth to specific depth, we need to re-arrange the actual heavy `Splat` structs to match this new order.
    -   It iterates through the sorted list:
        1.  Extracts the original ID: `index = splat_index[i] & 0xFFFFFFFF`.
        2.  Copies the splat from the main buffer (`splats[index]`) to the temporary buffer (`temp_splats[i]`).
    -   Result: `temp_splats` now contains the full Gaussian data, perfectly ordered from back-to-front.

4.  **Copy Back (Line 45)**:
    -   `memcpy(...)`
    -   Bulk copies the correctly ordered data from `temp_splats` back into `splats`.
    -   Now the `splats` buffer is ready for the GPU to draw sequentially.

---

## Summary
In the flowchart, `splat_utils.mm` is the **Sorter**.
-   **Input**: Unsorted list of Depth+IDs.
-   **Process**: Quicksort (or Introsort) the IDs, then shuffle the heavy data to match.
-   **Output**: Sorted `Splat` buffer that allows for correct Alpha Blending.
